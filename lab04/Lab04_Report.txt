1. The Deadlock (Phase 2):
In the `deadlock_simulation.py` script, explain step-by-step how the "Circular Wait" condition occurred between Model A and Model B.
Answer: Circular Wait occurred because Model A acquired GPU 0 and waited for GPU 1, while Model B simultaneously acquired GPU 1 and waited for GPU 0. Both models held one resource while waiting for the other in a closed dependency loop, causing both threads to block indefinitely.
2. The Solution (Phase 3):
By changing the code in `deadlock_avoidance.py` so that Model B also requests GPU 0 first, how did this specifically break the "Circular Wait" condition? 
Answer: By forcing Model B to request GPU 0 before GPU 1 (matching Model A's order), Circular Wait was broken because both models now contend for the same initial lock (gpu_0_lock). Whichever model acquires GPU 0 first finishes its entire task and releases all locks before the second model can acquire any GPU.
3. Starvation vs Deadlock (Phase 4):
Based on the results from `starvation_sim.py`:
- How is the final output of the Starvation script fundamentally different from the Deadlock script you ran in Phase 2?
Answer:In Deadlock, all threads are frozen and zero progress is made. In Starvation, the system continues running, but the Polite Model is severely deprived of CPU time while Greedy Models continuously capture the lock thousands of times.
- In your own words, explain how a process scheduler could use a technique called "Aging" to help the `Polite_Model` get a fair share of CPU time.
Answer: Aging works by gradually increasing the priority of a process the longer it waits in the ready queue. As Polite_Model waits, its priority grows high enough to eventually preempt greedy threads and acquire the resource fairly.
4. Deadlock Detection & Recovery (Phase 3.3 / Phase 5):
- How did the `timeout` parameter simulate the Deadlock Detection mechanism of an Operating System?
Answer:The timeout parameter acts as an OS Watchdog timer. If a thread cannot acquire a resource within the threshold (2.0s), it assumes a Deadlock has occurred rather than waiting forever.
- When the Deadlock was detected, what exact step did Model A take to perform "Recovery" and allow the rest of the system to continue?
Answer:When Model A timed out, it performed a rollback by releasing its already-acquired resource (gpu_0_lock.release()) and aborting its execution. This freed GPU 0 for Model B to finish successfully.
